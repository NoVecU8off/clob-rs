# Что предстоит сделать

Этапы ориентировочные, порядок может меняться. Отметки: `[ ]` — не начато,
`[~]` — в работе, `[x]` — готово. Текущее состояние — в [STATUS.md](STATUS.md).

## v0.2 — Производительность и типы заявок

- [ ] **Интрузивный список на ценовом уровне** → отмена и изменение за `O(1)`
      (сейчас отмена внутри уровня — `O(n)`).
- [ ] **Команда `Modify` / amend** — изменение цены/количества; смена цены или
      увеличение объёма теряет временной приоритет, уменьшение — сохраняет.
- [ ] **Post-only** — отклонять заявку, если она немедленно пересекла бы спред (maker-only).
- [ ] **Stop / stop-limit** — отложенные заявки, активируемые по триггерной цене.
- [ ] **Iceberg** — видимая и скрытая части объёма.
- [ ] Пул переиспользуемых аллокаций в матчинге (убрать `Vec` под исполненные id).

## v0.3 — Надёжность и реплей

- [ ] **Журнал событий (event sourcing)** — запись входного потока команд.
- [ ] **Реплей** — восстановление состояния из журнала, горячий резерв (реплика).
- [ ] **Снимки (snapshots)** состояния книги для ускорения восстановления.
- [ ] Версионирование формата журнала и снимков.

## v0.4 — Market data

- [ ] **L2-снимок** (агрегированная глубина по уровням) и **L3** (по заявкам).
- [ ] **Инкрементальные обновления** книги вместо полного снимка.
- [ ] Поток сделок (trade tape) как отдельный канал.
- [ ] Консистентность номеров последовательности между data-каналами.

## v0.5 — Сеть и масштаб

- [ ] **Асинхронный шлюз** (tokio): приём команд по TCP/WebSocket, рассылка событий.
- [ ] **Шардирование по инструментам** — один однопоточный движок на инструмент.
- [ ] Бинарный протокол кодирования команд/событий.
- [ ] Backpressure и ограничение скорости на шлюзе.

## Кросс-функциональное (по мере необходимости)

- [ ] **Счёт/владелец заявки** и **self-trade prevention** (запрет самосведения).
- [ ] **Pre-trade risk** в Gateway: лимиты позиции, ценовые коридоры, размер тика/лота.
- [ ] **Комиссии** maker/taker и расчёт в событиях сделок.
- [ ] **Criterion-бенчмарки** с гистограммами латентности (p50/p99/p99.9).
- [ ] **Property-based тесты** (например, `proptest`): инварианты книги при случайных потоках.
- [ ] **Fuzzing** конвейера команд.
- [ ] **Rustdoc** по всему публичному API + публикация на docs.rs.
- [ ] **Файлы лицензий** `LICENSE-MIT` и `LICENSE-APACHE`.

## Осознанно вне области (пока)

- Клиринг и расчёты (settlement) — отдельная подсистема ниже по потоку.
- Кросс-инструментные стратегии матчинга (спреды, мультилег).
- Pro-rata и иные алгоритмы распределения (сейчас только price-time); закладывается
  через абстракцию политики уровня, когда понадобится.
