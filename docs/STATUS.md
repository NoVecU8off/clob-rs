## Типы заявок и time-in-force

- Типы: `Limit`, `Market`, `Stop` (стоп-маркет), `StopLimit` (стоп-лимит), `Iceberg` (видимый peak + скрытый резерв).
- Time-in-force: `Gtc` (встаёт в книгу), `Ioc` (исполнить сейчас, остаток отменить), `Fok` (исполнить целиком или отклонить), `PostOnly` (только мейкер: отклонить с `WouldCross`, если немедленно пересекла бы спред).

## Изменение заявок (amend)

- `Modify` меняет цену и/или количество стоящей заявки, сохраняя `order_id`.
- Уменьшение количества при той же цене сохраняет приоритет (правка на месте, `O(1)`).
- Смена цены или увеличение количества — потеря приоритета: заявка снимается и заново сводится (при пересечении спреда исполняется).

## Стоп-заявки

- `Stop` (стоп-маркет) и `StopLimit` (стоп-лимит) «спят» в отдельной книге вне основной и не видны в `depth()` / `len()`; их число — в `Clob::pending_stops()`.
- Триггер — **цена последней сделки**: buy-stop активируется при `last >= trigger`, sell-stop — при `last <= trigger`. Если рынок уже за триггером, стоп срабатывает сразу при приёме.
- При срабатывании эмитится `Triggered`, затем заявка проходит обычное сведение: `Stop` — как рыночная, `StopLimit` — как лимит по своей цене с учётом TIF (вкл. предпроверки `Fok` / `PostOnly` на момент активации).
- Активация **каскадная**: сделки сработавшего стопа двигают цену и могут активировать следующие стопы (порядок — по времени приёма). Каскад детерминирован и конечен.
- `Cancel` снимает спящий стоп; `Modify` спящего стопа пока не поддерживается.

## Iceberg

- `Iceberg` показывает в книге только видимую часть (peak, `display`); остаток объёма лежит в скрытом резерве и не виден в `depth()` / `len()` / `available_qty()`.
- Когда видимый peak полностью сводится, из резерва доливается новый peak `min(display, hidden)` и встаёт **в хвост** своего ценового уровня — позади всех уже отображённых заявок (потеря временного приоритета).
- Достаточно крупный встречный приказ сводит весь айсберг за один проход (послойно, включая скрытую часть); приоритет теряется только относительно других заявок уровня.
- Как тейкер айсберг сводится на полный `qty` (как обычный лимит); `display` действует только на встающий в книгу остаток. `display >= qty` → обычная полностью видимая заявка. Осмысленные TIF — `Gtc` и `PostOnly`.
- Долив не эмитит событий (виден в `depth()`); `Cancel` снимает айсберг целиком вместе с резервом; `Modify` трактует `qty` как новый полный объём, сохраняет `display` и переставляет заявку заново (теряя приоритет).

## Счёт/владелец и self-trade prevention (STP)

- Заявка несёт опциональные `owner: AccountId` (примитив-`u64`; `0` — аноним / не задан) и `stp: StpMode` (`Off` | `CancelTaker` | `CancelMaker` | `CancelBoth`); задаются билдерами `NewOrder::with_owner(id)` / `with_stp(mode)`, по умолчанию `owner = 0`, `stp = Off`. STP — строго opt-in: дефолтные заявки ведут себя как раньше.
- Для ядра `owner` — **непрозрачный токен равенства**: движок его не интерпретирует, только сравнивает. Аутентификация владельца — забота слоя выше (`clob-server`), ядро принимает проштампованный `owner` как доверенный.
- STP проверяется **в момент сведения, по каждому встречному мейкеру**: при `taker.stp != Off && taker.owner != 0 && taker.owner == maker.owner` вместо сделки применяется политика **агрессора** (taker governs) — `stp` мейкера не читается. `CancelTaker` снимает остаток агрессора (мейкер цел); `CancelMaker` снимает встреченный стоящий ордер и агрессор идёт дальше по очереди; `CancelBoth` снимает оба. Чужая ликвидность при этом сводится нормально. Все снятия по STP эмитят `Canceled`.
- STP применяется и к **сработавшему стопу**: он несёт свои `owner` / `stp` и на активации действует как агрессор.
- `owner` хранится инлайном на стоящей заявке (`RestingOrder`), **переживает снимок и реплей** (журнал `CLBW` версия `2`, снимок `CLBS` версия `3`) и **не утекает** в публичные проекции market data (L2/L3/лента остаются обезличенными).

## Pre-trade risk (тик/лот, коридор, лимиты позиции)

- Подключается через `Clob::with_risk(RiskConfig)` / `PersistentClob::open_with_risk(path, cfg)`; `Clob::new()` и `PersistentClob::open` остаются **без проверок** (риск-контроль строго opt-in, дефолт off). `RiskConfig` собирается билдерами `with_tick` / `with_lot` / `with_price_band(band_ticks)` / `with_position_limit`; значение `0`/`1` отключает проверку.
- **Тик/лот.** Цена кратна `tick_size` (лимит-цена, `trigger` стопа, оба поля stop-limit, цена айсберга); `qty` и `display` айсберга кратны `lot_size`. Market пропускает ценовые проверки (цены нет), лот к `qty` применяется.
- **Ценовой коридор.** Окно `[mid − band_ticks·tick, mid + band_ticks·tick]` вокруг `mid = (best_bid + best_ask) / 2` (tick = `max(tick_size, 1)`). На холодной/односторонней книге (mid не определён) коридор пропускается; стопы (стоят вне рынка) и market — мимо. Референс берётся из книги, но Gateway его не читает сам — `Clob` прокидывает mid в контекст (stage separation сохранён).
- **Лимиты позиции (нетто-знаковые, worst-case).** Только для `owner != 0` (аноним освобождён). Покупка: `net + открытый_объём_покупок + qty ≤ limit`; продажа: `−net + открытый_объём_продаж + qty ≤ limit`. Открытый объём учитывает полный остаток айсберга (видимый + скрытый резерв). На `Modify` собственный текущий вклад заявки вычитается, затем добавляется новый `qty`.
- **Учёт ведёт книга** (единый источник истины): `match_against` видит обоих участников сделки, поэтому нетто-позиция (`i128`) и открытый объём обновляются внутри книги на `insert` / `cancel` / `reduce` / сведении / STP-`detach`; `Clob`/движок только читают агрегаты для валидации. Нетто-позиция **переживает** снимок (`CLBS` версия `3`, секция нетто, счета отсортированы по `AccountId`) и реплей; журнал (`CLBW`) не меняется. `RiskConfig` не персистится — приложение задаёт его при открытии (на реплее — **тот же** конфиг, иначе история разойдётся).
- Новые `RejectReason`: `TickSize`, `LotSize`, `PriceBand`, `PositionLimit`.

## Комиссии (maker/taker)

- Подключается через `Clob::with_fees(FeeConfig)` / `Clob::with_risk_and_fees(risk, fees)` и `PersistentClob::open_with_fees(path, fees)` / `open_with_risk_and_fees(path, risk, fees)`; `Clob::new()` и прежние конструкторы остаются **без комиссий** (дефолт off). `FeeConfig` собирается билдерами `with_maker_ppm` / `with_taker_ppm`; ставка `0` отключает сторону.
- **Модель — ppm от нотионала.** `fee = price · qty · rate_ppm / 1_000_000` (промежуточно `i128` с насыщением, округление **усечением к нулю** — симметрично для комиссии и ребейта). Ставки **знаковые** (`i64`): положительная — комиссия, **отрицательная ставка мейкера — ребейт** (выплата мейкеру, отрицательный `maker_fee`).
- **Где считается.** На каждой сделке в точке её рождения (движок, колбэк `on_trade`, где видны оба участника). Облагается **весь исполненный объём**, включая скрытый резерв айсберга — принт на каждый сведённый слой. STP-отмены и прочие нефактические события комиссию не несут.
- **Вывод — в событии.** Два новых поля `Event::Trade`: `taker_fee: i64` и `maker_fee: i64`. По принципу «события на выходе, не состояние внутри» ядро комиссии **не накапливает** — суммирование/расчёт делает слой клиринга (вне области). Поэтому **снимок не меняется** (`CLBS` остаётся версии `3`), журнал не затронут, а `FeeConfig` **не персистится** — приложение задаёт его при открытии (комиссии не влияют на состояние книги, только на выводимые числа).
- **Обезличенность.** `taker_fee` / `maker_fee` приватны и в публичные каналы market data (L2/L3-снимки, инкременты, лента `TapeTrade`) **не попадают**.

## Market data (снимки, инкрементальные обновления и лента сделок)

- `Clob::l2_snapshot(depth)` — **market-by-price**: агрегированная глубина по уровням (`L2Snapshot`: `bids` / `asks` из `L2Level { price, qty }`), лучшая цена первой, не более `depth` уровней на сторону.
- `Clob::l3_snapshot()` — **market-by-order**: книга по отдельным заявкам (`L3Snapshot`: `bids` / `asks` из `L3Order { id, side, price, qty }`), best-first по цене и FIFO внутри уровня — то есть видна позиция в очереди.
- Оба снимка несут текущий `seq` — якорь для будущих инкрементальных обновлений.
- Проекция **публичная и обезличенная**: для iceberg отдаётся только видимый peak, скрытый резерв в снимки не попадает (приватность определяется тем, что участник *выставил*, а не гранулярностью фида); владелец/счёт у заявки в модели пока отсутствует.
- Реализовано как read-проекция (`src/marketdata.rs`) поверх `depth()` / `resting_orders()` — детерминированное ядро не затронуто.
- **Инкрементальные L2-обновления.** `L2Feed::apply(&events, book)` отдаёт `L2Update` — дельты только изменённых ценовых уровней одной команды (уровень с `qty == 0` — удаление), с тем же `seq`. Потребитель берёт `l2_snapshot` (или `L2Feed::from_book`) как базу и применяет дельты, не пересылая всю книгу. Затронутые уровни выводятся из событий, новый объём читается из книги (`OrderBook::level_qty`), поэтому дельты точны и при айсберг-доливе, и при modify-репрайсе. Скрытый резерв айсберга в дельты не попадает.
- **Инкрементальные L3-обновления (market-by-order).** `L3Feed::apply(&events, book)` отдаёт `L3Update` — пер-заявочные дельты `L3Delta` (`Added { id, side, price, qty }` в хвост уровня / `Reduced { id, qty }` с сохранением позиции / `Removed { id }`), с тем же `seq`. Затронутые уровни выводятся из событий (как у L2), но порядок очереди внутри уровня сверяется с книгой (`OrderBook::level_orders`): дельты — это диф старого списка уровня против нового, упорядоченный `Removed` → `Reduced` → `Added`. Поэтому долив айсберга и потеря приоритета при amend выражаются как remove-then-add (перестановка в хвост) и точно воспроизводят FIFO книги. `L3Feed::from_book` сеет фид из снимка `l3_snapshot` с тем же `seq`. Скрытый резерв айсберга в дельты не попадает.
- **Сквозная нумерация каналов.** Все каналы market data якорятся на `seq` команды через единый `command_seq`: снимки несут `current_seq()`, инкременты `L2Update` / `L3Update` и принты `TapeTrade` — тот же `seq` команды. Для одной команды все каналы несут один `seq`, так что потребитель применяет инкременты с `seq` больше снимочного и сводит каналы между собой по общему якорю.
- **Лента сделок (trade tape).** `TradeTape::apply(&events)` извлекает из потока событий публичные обезличенные принты `TapeTrade { seq, price, qty, taker_side }` — по одному на каждый `Event::Trade`, в порядке исполнения; возвращает принты команды и копит их в ограниченной кольцевой истории (`new()` — без предела, `bounded(cap)` — последние `cap`; чтение — `recent()` / `last()` / `len()` / `is_empty()`). В отличие от L2/L3-проекций лента **book-free** — `apply` берёт только `&[Event]` и книгу не читает, поэтому её может вести потребитель, видящий лишь поток событий. Принт несёт `seq` команды — общий якорь с книжным каналом. Обезличенность — о владельце и идентификаторах (id заявок в ленту не попадают); исполненный объём, наоборот, публичен и печатается **полностью**: проход по айсбергу даёт принт на каждый сведённый слой, включая объём из скрытого резерва (книга прячет *стоящий* резерв, лента печатает *исполненное*).

## Персистентность (журнал, снимки и реплей)

- `PersistentClob` оборачивает `Clob` и ведёт write-ahead журнал входных команд: команда сериализуется и сбрасывается на диск (`fsync`) **до** возврата событий — подтверждённая заявка переживает падение процесса.
- Восстановление (`PersistentClob::open`) — **реплей**: журнал переподаётся в свежий `Clob`; за счёт детерминизма книга, `order_id` и `seq` воспроизводятся точно. Отклонённые gateway команды тоже журналируются (они расходуют `seq`).
- Формат журнала — собственный бинарный (`std`-only): заголовок сегмента `magic "CLBW"` + версия, записи команд с varint-полями, блоки кадрируются длиной + CRC32. Групповой коммит — `submit_batch` (один `fsync` на пачку). Прерванная последняя запись отсекается по CRC.
- **Снимки.** `checkpoint()` пишет снимок полного детерминированного состояния (счётчики секвенсора `seq`/`next_order_id`, цена последней сделки, стоящие заявки в порядке приоритета вместе со скрытыми резервами айсбергов, спящие стопы, нетто-позиции счетов) и ротирует журнал, оставляя только хвост. `open` грузит снимок и переигрывает **только команды журнала после снимка** — восстановление не переигрывает весь поток. Формат снимка — `magic "CLBS"` + версия, varint-поля, общий кадр с CRC32 (тот же кодек). Запись атомарна: временный файл → `fsync` → `rename`.
- **Крэш-безопасность чекпойнта.** Согласование снимка и журнала идемпотентно по `seq`: при восстановлении применяются только команды с `seq` больше покрытого снимком. Поэтому прерванный посреди чекпойнт (снимок записан, журнал ещё не повёрнут) не даёт ни двойного применения, ни потери команд. Битый снимок (CRC не сходится) → `JournalError::CorruptSnapshot`.
- Низкоуровневый доступ: `Journal` (писатель), `read_commands` (читатель потока команд).

## Известные ограничения

- **Стопы триггерятся по цене последней сделки** (не по котировкам); спящие стопы не отражаются в глубине/`len()`; amend спящего стопа не поддерживается.
- **Iceberg**: скрытый резерв не виден в `depth()` / `len()` / `available_qty()` и не учитывается в проверке ликвидности `Fok`; долив видимой части не порождает событий; `Modify` айсберга всегда переставляет заявку (теряя приоритет).
- **Self-trade prevention** проверяется только на `New`: `Modify` (amend) пере-сводится без STP; предпроверки `Fok` / post-only считают встречный объём целиком, не вычитая собственную ликвидность владельца. `owner` приватен — в L2/L3-снимки, инкременты и ленту сделок не попадает. Политика `decrement` (срез обоих на overlap) пока не реализована.
- **Персистентность — журнал + снимки + реплей** (`PersistentClob`): снимок и ротацию журнала запускает только явный `checkpoint()` (автоматических чекпойнтов по таймеру/объёму нет — это решает приложение, ядро остаётся без часов); per-command `fsync` медленный (для пропускной способности — групповой коммит `submit_batch`); сбой `fsync` в середине потока следует считать фатальным (перезапуск и восстановление из журнала).
- **Нет сети** — библиотека встраиваемая, без шлюза.
- **Market data**: снимки L2/L3, инкрементальные дельты L2 (`L2Feed`) и L3 (`L3Feed` — market-by-order с позицией в очереди) и лента сделок (`TradeTape`); все каналы якорятся на один `seq` команды. Книжные фиды со-локальны — `apply` читает книгу; лента, наоборот, **book-free** — потребитель ведёт её по одному потоку событий. (Этап v0.4 закрыт.)
- **Pre-trade risk** (opt-in `RiskConfig`): тик/лот, ценовой коридор от mid, лимиты позиции (нетто worst-case). Спящие стопы не учитываются в открытом объёме до срабатывания; `RiskConfig` не персистится — приложение задаёт его при открытии (на реплее — тот же).
- **Комиссии** maker/taker (opt-in `FeeConfig`): ставки в ppm от нотионала, знаковые (ребейт мейкера). Считаются на каждой сделке и выводятся в `Event::Trade` (`taker_fee` / `maker_fee`); ядро их **не накапливает** (суммирование — слой клиринга, вне области), `FeeConfig` **не персистится**. Округление — усечение к нулю.
- **Логическое время**: `timestamp` приравнен к `seq` (отдельные часы не вводятся ради детерминизма).
