## [Unreleased]

### Добавлено

- **Stop и stop-limit (`OrderType::Stop` / `OrderType::StopLimit`)** — отложенные заявки с триггерной ценой. Конструкторы `NewOrder::stop(side, trigger, qty)` (на срабатывании ведёт себя как рыночная) и `NewOrder::stop_limit(side, trigger, limit, qty)` (на срабатывании — лимитная по цене `limit`). Gateway отклоняет стоп с `trigger == 0` и стоп-лимит с `trigger == 0` или `price == 0` как `InvalidPrice`. Срабатывание привязано к **цене последней сделки**: buy-stop активируется при `last >= trigger`, sell-stop — при `last <= trigger`. До срабатывания заявка «спит» в отдельной книге стопов и **не видна** в `depth()` / `len()` книги; если рынок уже за триггером, стоп срабатывает сразу при приёме. Активация **каскадная**: сделки сработавшей заявки двигают цену и могут активировать следующие стопы (порядок активации — по времени приёма, детерминированно). `Cancel` снимает спящий стоп; `Modify` спящего стопа пока не поддерживается (отклоняется как `UnknownOrder`).
- **Событие `Triggered`** — стоп-заявка сработала и сейчас проходит сведение; далее идут обычные события исхода (`Trade` / `Resting` / `Filled` / `Canceled`), как у `New` после `Accepted`. События активации тегируются `seq` текущей команды, идентичность заявки — по `order_id`.
- **`Clob::pending_stops()`** — число спящих (ещё не сработавших) стоп-заявок.
- **Post-only (`TimeInForce::PostOnly`)** — заявка «только мейкер»: если лимит немедленно пересёк бы спред, она отклоняется (`RejectReason::WouldCross`) до `Accepted` и в книгу не попадает; иначе ведёт себя как `Gtc` и встаёт в книгу. Проверка — в движке, до приёма (как предпроверка `Fok`); для `Market` пересечение считается всегда.
- **Команда `Modify` (amend)** — изменение цены и/или количества стоящей заявки (`Command::Modify`, `ModifyOrder::new`). Уменьшение количества при той же цене сохраняет временной приоритет (правка на месте за `O(1)`); смена цены или увеличение количества теряет приоритет — заявка снимается и заново проходит сведение с тем же `order_id`, при пересечении спреда исполняется.
- **Событие `Modified`** — подтверждение приёма `Modify`; далее следуют события исхода (`Resting` / `Trade` / `Filled`), как у `New` после `Accepted`.

### Изменено

- **Order book** — внутри ценового уровня интрузивный двусвязный FIFO-список вместо `VecDeque`; узлы заявок хранятся в общей арене (слаб) со списком свободных слотов. Отмена внутри уровня теперь `O(1)` вместо `O(n)`.
- **Matching Engine** — убрана аллокация `Vec` под идентификаторы исполненных заявок: мейкер снимается из индекса прямо в цикле сведения, а слот узла возвращается в пул.
- **Matching Engine** — общий путь сведения (предпроверки TIF, матчинг, постановка остатка/отмена) вынесен в `settle` / `precheck` и переиспользуется новыми заявками, amend и активацией стопов; добавлены книга стопов и каскадная активация по цене последней сделки. `Modify`, породивший сделку, теперь тоже может активировать стопы.

Остальное запланированное см. в [ROADMAP.md](ROADMAP.md).

## [0.1.0] — 2026-06-20

Первый релиз. Детерминированное ядро CLOB с конвейером
`Gateway → Sequencer → Matching Engine → Output`.

### Добавлено

- **Конвейер `Clob`** — единая точка входа `submit()` / `submit_into()`, связывающая все стадии.
- **Gateway** — валидация заявок: отказ при нулевом количестве (`ZeroQuantity`) и нулевой цене лимитной заявки (`InvalidPrice`).
- **Sequencer** — монотонные номера последовательности и идентификаторы заявок для детерминированного порядка.
- **Matching Engine** — сведение по price-time priority (FIFO внутри ценового уровня).
- **Order book** — `BTreeMap` ценовых уровней по каждой стороне, `VecDeque` для FIFO внутри уровня, `HashMap` индекс заявок для отмены.
- **Типы заявок** — `Limit`, `Market`.
- **Time-in-force** — `Gtc`, `Ioc`, `Fok`.
- **События** — `Accepted`, `Trade`, `Resting`, `Filled`, `Canceled`, `Rejected`.
- **Доступ к книге** — `best_bid`, `best_ask`, `spread`, `depth`, `len`, `contains`, `available_qty`.
- **Примеры** — `examples/basic.rs` (демонстрация событий и книги), `examples/throughput.rs` (нагрузочный прогон).
- **Тесты** — 12 интеграционных тестов на матчинг, приоритет, TIF, отмену и инварианты книги.
- **Документация** — папка `docs/` (статус, архитектура, журнал обновлений, roadmap).

### Особенности реализации

- Целочисленные цены и количества (`u64`), без чисел с плавающей точкой.
- Ядро без внешних зависимостей (только `std`).
- Редакция Rust 2024; `release`-профиль с LTO и `panic = "abort"`.
